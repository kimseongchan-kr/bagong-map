# 기능 명세: 참여 신청·승인·수정·취소

**작성일**: 2026-10-06
**상태**: 초안 — 사용자 검토·승인 전
**브랜치**: 별도 기능 브랜치 미생성
**입력**: 노션 PRD v0.1을 기준으로 전체 범위를 기능별로 분해하라는 사용자 요청

## 목적·범위·비목표

참가자가 주문 내용을 신청하고 모집자가 승인하며, 수정·취소가 승인 상태와 합계에 일관되게 반영된다.

- 포함: 개별 메뉴 신청, 모집자 승인, 승인 전 수정, 모집 중 재승인, 상태별 참여 취소와 합계 갱신.
- 비목표·경계: 균등 분할 신청의 상세 입력 규칙은 제안·미정으로 관리한다. 모집 정보 자체 수정, 외부 주문 취소·환불은 이 기능 범위에 포함하지 않는다.

확정은 원본 PRD의 합의 내용이다. 제안·미정은 승인되지 않았다. 아래 시나리오와 SC는 확정 요구사항도 검증 가능한 문장으로 구체화한 검토용 제안이며, 실제 검증 통과를 의미하지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 신청과 승인 (P1)

개별 메뉴 참가자가 메뉴·금액을 신청하고 모집자가 승인한다.

**우선순위 이유**: 승인된 주문만 목표 충족에 반영하기 위해 필요하다.
**개별 검증**: 모집자 음식값과 대기 신청을 준비하고 승인 전후 합계를 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 모집 중 개별 메뉴 모집이 있을 때 **행동**: 참가자가 메뉴·금액을 신청하면 **기대 결과**: 신청은 저장되지만 승인 전에는 목표 음식값 합계에 반영되지 않는다. [AC-04]
2. **주어진 조건**: 대기 신청이 있을 때 **행동**: 모집자가 승인하면 **기대 결과**: 승인 음식값이 한 번만 합계에 반영된다. [AC-04]

### 사용자 이야기 2 — 신청 수정과 재승인 (P1)

참가자가 모집 중 신청을 수정하고 필요하면 재승인을 받는다.

**우선순위 이유**: 수정된 음식값을 검토 없이 승인 합계에 넣지 않는다.
**개별 검증**: 승인 신청을 수정한 뒤 재승인 전후 합계를 확인한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 승인 전 신청일 때 **행동**: 참가자가 신청 내용을 수정하면 **기대 결과**: 자유롭게 수정할 수 있다. [REQ-11]
2. **주어진 조건**: 모집 중 승인 참가자일 때 **행동**: 메뉴·금액을 수정하면 **기대 결과**: 재승인 대기로 전환되고 해당 음식값은 합계에서 제외된다. [AC-12]
3. **주어진 조건**: 재승인 대기 신청이 있을 때 **행동**: 모집자가 다시 승인하면 **기대 결과**: 수정된 음식값만 한 번 반영된다. [AC-12]
4. **주어진 조건**: 마감 이후일 때 **행동**: 직접 메뉴 수정을 시도하면 **기대 결과**: 직접 수정할 수 없고 채팅 변경 요청으로 안내한다. [AC-13]

### 사용자 이야기 3 — 참여 취소 (P1)

참가자가 모집 상태에 맞는 절차로 취소한다.

**우선순위 이유**: 주문 전후의 다른 책임과 합계 갱신을 반영한다.
**개별 검증**: 모집 중·마감 후 주문 전·주문 완료 상태별 취소를 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 모집 중일 때 **행동**: 참가자가 취소하면 **기대 결과**: 자유 취소되며 승인 인원·금액이 갱신된다. [AC-14]
2. **주어진 조건**: 마감 후 주문 전일 때 **행동**: 참가자가 취소 요청하면 **기대 결과**: 참여가 즉시 삭제되지 않고 모집자 승인 후 취소된다. [AC-14]
3. **주어진 조건**: 주문 완료로 표시된 모집일 때 **행동**: 참가자가 일방 취소를 시도하면 **기대 결과**: 일방 취소는 처리하지 않고 채팅 협의를 안내한다. [AC-15 연결]

### 경계 사례

- 자기 모집에 별도 신청·같은 모집에 중복 신청·거절/취소 후 재신청: 허용 규칙은 미정이다.
- 승인과 마감·수정·취소가 동시 발생: 일관성 기준은 AC-18 제안 채택 후 설계·검증한다.
- 재승인 대기: 음식값 제외는 확정이나 승인 인원·정확한 장소·채팅 처리 세부 규칙은 검토가 필요하다.
- 취소 요청 중 모집자가 주문 완료를 표시함: 요청의 처리 가능 시점과 우선순위는 미정이다.
- 실제 주문과 표시 시점 차이: 외부 주문 사실을 자동 판단하지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001 · 확정**: 개별 메뉴 참가자가 메뉴·금액을 입력하여 신청하며 모집자가 승인한다. 승인 음식값만 목표 합계에 반영한다. 출처: REQ-05.
- **FR-002 · 확정**: 승인 전 자유 수정, 승인 후 모집 중 수정 시 재승인, 마감 후 채팅 변경 요청 규칙을 적용한다. 출처: REQ-11.
- **FR-003 · 확정**: 재승인 전 해당 참가자 음식값을 합계에서 제외하고 재승인 후 수정 금액을 반영한다. 출처: REQ-11, PRD 8장.
- **FR-004 · 확정**: 모집 중 자유 취소, 마감 후 주문 전 모집자 승인 취소, 실제 주문 후 채팅 협의를 적용한다. 출처: REQ-12.
- **FR-005 · 확정**: 취소·수정 후 합계를 갱신하며 자동 마감된 모집은 자동 재개하지 않는다. 출처: REQ-14.
- **FR-006 · 제안**: 중복 신청·반복 승인·동시 승인/취소/마감으로 인원·금액을 중복 반영하거나 마감 후 승인하지 않는다. 출처: PRD 9장·11장, AC-18.
- **FR-007 · 제안**: 균등 분할 참가자는 메뉴별 금액 입력 대신 해당 계산 방식의 참여 신청을 한다. 상세 입력·변경 정책은 미정이다. 출처: PRD 6장.

### 주요 데이터 개념

- 신청: 참가자, 모집, 메뉴·금액, 승인 상태.
- 취소 요청: 마감 후 주문 전 참가자의 요청과 모집자 처리 결과.
- 승인 합계: 모집자와 승인 참가자의 음식값·인원. 재승인·취소 영향을 005/006과 공유한다.

## 완료 조건

### 측정 가능한 검증 결과 — 검토용 제안

- **SC-001**: 신청·승인·수정·재승인 과정에서 대기 금액은 제외되고 승인된 현재 음식값이 한 번 반영된다. [AC-04, AC-12]
- **SC-002**: 세 모집 상태에서 수정·취소 시나리오가 규칙에 맞게 처리된다. [AC-13~15]
- **SC-003**: 동시성 제안 채택 후 중복 승인·초과 인원·마감 후 승인으로 인한 상태/합계 위반이 0건이다. [AC-18]

이 기능의 검증 결과는 관련 PRD AC로 추적한다. 제품 성과 지표의 목표값·관찰 기간은 OPEN-07에서 별도로 결정한다.

## 가정·의존성·호환성

- 002의 인증·권한, 003의 모집 조건, 005의 상태, 006의 계산, 007의 채팅에 의존한다. 합계는 기능별로 다른 정의를 사용하지 않는다.
- 이 명세는 새 프로젝트에 적용한다. 기존 비공개 프로젝트의 코드·데이터를 가져오거나 기존 사용자 데이터를 이전하는 요구는 포함하지 않는다.
- 한국어 PC·모바일 웹 지원은 전체 제약이다. 기술 선택은 승인된 명세의 후속 설계에서 다룬다.
- 각 단계에 사용자 리뷰·검증을 포함한다. 현재 구현 계획·작업 목록·제품 코드는 작성하지 않았다.
