## 목적·범위·비목표

모집자가 수동 또는 자동으로 마감하고 외부 주문 이후 주문 완료를 표시하며, 필요한 경우 규칙에 맞게 재모집한다.

- 포함: 수동·시각·조건 마감, 신규 신청 제한, 모집자 포함 목표 계산, 주문 완료 표시, 모집자 결정 재모집.
- 비목표·경계: 실제 배달앱 주문·결제·배송 확인·환불은 수행하지 않는다. 수령·배분 완료와 모집 취소·종료 상태는 PRD 제안이며 확정된 상태로 구현하지 않는다.

확정은 원본 PRD의 합의 내용이다. 제안·미정은 승인되지 않았다. 아래 시나리오와 SC는 확정 요구사항도 검증 가능한 문장으로 구체화한 검토용 제안이며, 실제 검증 통과를 의미하지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 수동 마감과 시간 마감 (P1)

기본 수동 모드에서는 모집자가 마감하며 마감 시각 이후에는 신청을 받지 않는다.

**우선순위 이유**: 목표 충족과 마감을 별개로 통제한다.
**개별 검증**: 수동 모집에서 목표 충족·직접 마감·시각 도달을 각각 시험한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 수동 마감 모드일 때 **행동**: 목표 음식값 또는 인원을 충족하면 **기대 결과**: 조건 충족만으로 자동 마감하지 않는다. [AC-09]
2. **주어진 조건**: 모집 중일 때 **행동**: 모집자가 마감하거나 마감 시각이 지나면 **기대 결과**: 신규 신청을 받지 않는다. [AC-09]

### 사용자 이야기 2 — 자동 조건 마감 (P1)

선택한 자동 모드에서 승인 음식값 또는 승인 인원을 기준으로 마감한다.

**우선순위 이유**: 실제 승인 참여를 기준으로 목표를 충족한다.
**개별 검증**: 두 계산 방식의 목표 직전·충족·대기 포함 사례를 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 개별 메뉴 자동 모드, 목표 20,000원, 모집자 9,000원일 때 **행동**: 참가자 11,000원이 승인되면 **기대 결과**: 합계 20,000원으로 마감하며 대기 금액과 배달비는 포함하지 않는다. [AC-10]
2. **주어진 조건**: 균등 분할 자동 모드, 목표 3명일 때 **행동**: 모집자 외 2명이 승인되면 **기대 결과**: 목표 인원에 도달하여 마감하며 대기 신청자는 세지 않는다. [AC-11]

### 사용자 이야기 3 — 주문 완료와 재모집 (P1)

모집자는 외부 주문 후 완료 표시를 하고 필요한 주문 전 상태에서 재모집한다.

**우선순위 이유**: 외부 주문의 직접 표시와 모집 상태를 구분한다.
**개별 검증**: 주문 완료 표시와 주문 전 재모집·합계 감소를 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 외부 주문을 마친 모집자일 때 **행동**: 주문 완료로 표시하면 **기대 결과**: 참가자가 상태를 확인하고 일방 취소 대신 협의 안내를 받는다. [AC-15]
2. **주어진 조건**: 자동 마감된 모집일 때 **행동**: 취소·변경으로 승인 합계가 줄면 **기대 결과**: 자동으로 재개하지 않는다. [AC-13, REQ-14]
3. **주어진 조건**: 재모집이 허용된 주문 전 상태일 때 **행동**: 모집자가 재모집하면 **기대 결과**: 합의한 새 마감 시각 규칙에 따라 신규 신청을 다시 받는다. [AC-16, 규칙 결정 대기]

### 경계 사례

- 등록 시 모집자만으로 목표 충족: 즉시 마감 또는 최소 참여 인원 조건이 미정이다.
- 목표 미달로 시각 마감: 취소·연장·주문 선택 규칙이 미정이다.
- 마감 당시 대기 신청과 승인 경합: 대기 신청 처리·마감 후 승인 허용 여부의 세부 규칙을 정한다.
- 재모집 시 과거 마감 시각을 유지함: 시각 갱신과 목표 변경 허용 규칙이 미정이다.
- 주문 완료 표시 실수: 되돌리기 권한과 조건은 미정이다.

## 요구사항

### 기능 요구사항

- **FR-001 · 확정**: 수동 마감을 기본으로 하고 자동 마감은 선택 사항으로 제공한다. 출처: REQ-09.
- **FR-002 · 확정**: 모집자가 마감하거나 마감 시각이 지나면 신규 신청을 차단한다. 출처: REQ-09.
- **FR-003 · 확정**: 개별 메뉴 자동 마감은 승인 음식값 합계가 목표 이상일 때 적용하며 모집자 음식값은 포함하고 배달비는 제외한다. 출처: REQ-10.
- **FR-004 · 확정**: 균등 분할 자동 마감은 모집자를 포함한 승인 인원이 목표 인원에 도달할 때 적용한다. 출처: REQ-10.
- **FR-005 · 확정**: 외부 주문 이후 모집자가 주문 완료를 표시하고 참가자가 확인한다. 시각 마감은 주문 완료를 의미하지 않는다. 출처: REQ-13, PRD 8장.
- **FR-006 · 확정**: 취소·수정 후 합계를 갱신하지만 자동 마감된 모집을 자동 재개하지 않는다. 재모집은 모집자가 결정한다. 출처: REQ-14.
- **FR-007 · 제안**: 조건과 마감의 동시 갱신에서도 마감 후 승인이나 목표 인원 초과를 방지한다. 출처: AC-18, PRD 9장.
- **FR-008 · 제안**: 수령·배분 완료, 모집 취소·종료의 주체·조건을 별도 결정한 뒤 상태로 추가한다. 출처: PRD 8장, OPEN-10.

### 주요 데이터 개념

- 모집 상태: 모집 중, 마감·주문 전, 주문 완료. 수령·배분 완료와 모집 취소는 제안 상태다.
- 마감 조건: 수동/자동 선택, 마감 시각, 목표 음식값 또는 인원.
- 주문 완료 표시: 모집자가 외부 주문 이후 기록하는 상태이며 주문의 독립적 증명이 아니다.

## 완료 조건

### 측정 가능한 검증 결과 — 검토용 제안

- **SC-001**: 수동·시각 마감과 두 자동 마감 방식의 모든 시나리오를 통과한다. [AC-09~11]
- **SC-002**: 합계가 줄어도 자동 재개가 0건이고 재모집은 합의한 사용자 행동으로만 수행된다. [AC-13, AC-16]
- **SC-003**: 주문 완료 표시가 참가자에게 반영되며 일방 취소가 제한된다. [AC-15]
- **SC-004**: 004와의 동시성 통합 검증을 통과한다. 제안과 경계 규칙 확정 전에는 검증 대기다. [AC-18]

이 기능의 검증 결과는 관련 PRD AC로 추적한다. 제품 성과 지표의 목표값·관찰 기간은 OPEN-07에서 별도로 결정한다.

## 가정·의존성·호환성

- 004가 제공하는 승인 인원·음식값과 취소·재승인 변화를 사용한다. 006의 표시 부담액과 자동 마감용 음식값은 구분한다.
- 이 명세는 새 프로젝트에 적용한다. 기존 비공개 프로젝트의 코드·데이터를 가져오거나 기존 사용자 데이터를 이전하는 요구는 포함하지 않는다.
- 한국어 PC·모바일 웹 지원은 전체 제약이다. 기술 선택은 승인된 명세의 후속 설계에서 다룬다.
- 각 단계에 사용자 리뷰·검증을 포함한다. 현재 구현 계획·작업 목록·제품 코드는 작성하지 않았다.
