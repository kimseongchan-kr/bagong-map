# 기능 명세: 모집별 그룹 채팅과 정확한 장소 안내

**작성일**: 2026-10-06
**상태**: 초안 — 사용자 검토·승인 전
**브랜치**: 별도 기능 브랜치 미생성
**입력**: 노션 PRD v0.1을 기준으로 전체 범위를 기능별로 분해하라는 사용자 요청
**PRD 연결**: REQ-06, REQ-07 · AC-05~06

[전체 범위·원본·협업 원칙](../README.md)

## 목적·범위·비목표

모집자와 승인 참가자가 정확한 장소를 확인하고 모집별 그룹 채팅에서 주문·수령·변경을 조율한다.

- 포함: 승인자용 장소·안내, 모집별 메시지 교환, 참여 상태에 따른 접근, 마감 후 변경·주문 후 취소 협의.
- 비목표·경계: 공개 커뮤니티·친구·정기 모임은 첫 버전 제외다. 채팅으로 합의한 내용을 주문 데이터에 자동 반영하거나 외부 주문·정산을 처리하지 않는다.

확정은 원본 PRD의 합의 내용이다. 제안·미정은 승인되지 않았다. 아래 시나리오와 SC는 확정 요구사항도 검증 가능한 문장으로 구체화한 검토용 제안이며, 실제 검증 통과를 의미하지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 승인 후 장소 확인 (P1)

승인 참가자가 음식 수령·식사 장소와 안내를 확인한다.

**우선순위 이유**: 공개 대략 위치만으로는 수령을 완료할 수 없다.
**개별 검증**: 승인 전후 같은 계정의 공개 상세·정확한 장소 접근을 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 해당 모집에서 승인된 참가자일 때 **행동**: 장소 안내를 열면 **기대 결과**: 정확한 수령·식사 장소를 확인할 수 있다. [AC-05]
2. **주어진 조건**: 승인 자격이 없는 계정일 때 **행동**: 정확한 장소를 직접 요청하면 **기대 결과**: 정확한 장소에 접근할 수 없다. [AC-05, 직접 요청 조건 제안]

### 사용자 이야기 2 — 모집별 메시지 교환 (P1)

모집자와 승인 참가자가 해당 모집에서 메시지를 교환한다.

**우선순위 이유**: 모임 방식과 주문 변경을 조율할 수 있다.
**개별 검증**: 두 모집과 각 승인 계정을 준비하여 메시지를 교환한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 모집자와 승인 참가자가 같은 모집에 있을 때 **행동**: 메시지를 보내면 **기대 결과**: 서로 해당 모집에서 메시지를 확인할 수 있다. [AC-06]
2. **주어진 조건**: 서로 다른 모집일 때 **행동**: 각각 메시지를 교환하면 **기대 결과**: 다른 모집의 메시지가 섞이지 않는다. [AC-06]
3. **주어진 조건**: 메시지 전송이 실패했을 때 **행동**: 전송 결과를 확인하면 **기대 결과**: 전송 성공으로 표시하지 않는다. [AC-06, 실패 동작 제안]

### 경계 사례

- 메시지 재전송·중복·연결 끊김: 표시·재시도·중복 처리 규칙은 미정이다.
- 권한 변경 직전 열린 채팅·장소 화면: 이미 열람한 정보와 이후 조회·전송의 처리 경계를 결정한다.
- 모집 종료 후 과거 채팅·장소 열람: 접근 종료와 보관 기간이 미정이다.
- 채팅 합의 후 데이터 수정: 실제 주문 정보에 반영하는 주체·절차는 OPEN-02/05에서 결정한다.

## 요구사항

### 기능 요구사항

- **FR-001 · 확정**: 모집자와 해당 모집의 승인 참가자만 그룹 채팅에 참여한다. 출처: REQ-07.
- **FR-002 · 확정**: 승인 참가자에게 정확한 수령·식사 장소를 제공한다. 출처: REQ-06.
- **FR-003 · 확정**: 마감 후 메뉴 변경 요청과 실제 주문 후 취소 협의는 채팅으로 진행한다. 출처: REQ-11, REQ-12.
- **FR-004 · 제안**: 채팅·장소 요청마다 해당 모집의 사용자 자격을 확인하고 다른 모집 정보를 섞지 않는다. 출처: PRD 11장, AC-05~06.
- **FR-005 · 제안**: 전송 실패를 성공으로 표시하지 않고 재시도 가능 여부를 안내한다. 출처: PRD 11장, AC-06.
- **FR-006 · 제안**: 참여 취소·탈퇴 후 이후 정확한 장소·채팅 접근을 차단한다. 재승인 대기의 접근은 미정이다. 출처: PRD 5장, OPEN-05.

### 주요 데이터 개념

- 모집별 대화: 하나의 모집과 그 대화에 접근 가능한 사용자.
- 메시지: 작성자·대상 모집·내용. 보관·삭제·전달 규칙은 미정이다.
- 정확한 장소 안내: 승인자에게 제공하는 수령·식사 장소와 안내. 공개 위치와 분리한다.

## 완료 조건

### 측정 가능한 검증 결과 — 검토용 제안

- **SC-001**: 모집자·승인자가 장소와 채팅에 접근하고 무관한 계정은 접근하지 못한다. [AC-05]
- **SC-002**: 두 모집 간 메시지 혼합이 0건이며 같은 모집의 두 계정이 메시지를 교환한다. [AC-06]
- **SC-003**: 실패 동작 채택 후 전송 실패가 성공으로 표시되는 사례가 0건이다. [AC-06]
- **SC-004**: PC·모바일 시험 환경에서 채팅과 장소 안내를 확인한다. 환경 확정 전에는 검증 대기다. [AC-17 일부, OPEN-11]

이 기능의 검증 결과는 관련 PRD AC로 추적한다. 제품 성과 지표의 목표값·관찰 기간은 OPEN-07에서 별도로 결정한다.

## 미정 사항과 승인 전 결정

- **Q-01 · 접근 수명** (OPEN-05, OPEN-08, OPEN-10): [NEEDS CLARIFICATION: 재승인·취소·탈퇴·종료 후 접근과 장소/메시지 보관·삭제·신고 처리를 정한다.]
- **Q-02 · 채팅 합의와 데이터** (OPEN-02, OPEN-05): [NEEDS CLARIFICATION: 마감 후 합의한 변경의 주문 데이터 반영 주체·권한·절차를 정한다.]
- **Q-03 · 전달·복구·시험 조건** (OPEN-06, OPEN-09, OPEN-11): [NEEDS CLARIFICATION: 공급자·비용, 전달 목표·실패/재전송/중복 표시, 백업·복구와 시험 환경을 정한다.]

질문은 관련 결정을 묶은 검토 항목이다. 결정되지 않은 동작을 구현자가 임의로 확정하지 않는다. 원본 OPEN 목록의 승인·변경도 사용자 검토 후 반영한다.

## 가정·의존성·호환성

- 002와 동일한 모집별 권한을 사용하고 004의 승인·재승인·취소, 005의 마감·주문·종료 상태를 따른다.
- 이 명세는 새 프로젝트에 적용한다. 기존 비공개 프로젝트의 코드·데이터를 가져오거나 기존 사용자 데이터를 이전하는 요구는 포함하지 않는다.
- 한국어 PC·모바일 웹 지원은 전체 제약이다. 기술 선택은 승인된 명세의 후속 설계에서 다룬다.
- 각 단계에 사용자 리뷰·검증을 포함한다. 현재 구현 계획·작업 목록·제품 코드는 작성하지 않았다.
