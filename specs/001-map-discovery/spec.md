# 기능 명세: 지도 탐색과 공개 모집 상세

**작성일**: 2026-10-06
**갱신일**: 2026-10-08
**상태**: 첫 구현 범위 승인(2026-10-08) — 전체 제품의 후속 항목은 미정 유지
**브랜치**: 별도 기능 브랜치 미생성
**입력**: 노션 PRD v0.1을 기준으로 전체 범위를 기능별로 분해하라는 사용자 요청
**PRD 연결**: REQ-01, REQ-06 · AC-01, AC-17 일부

## 목적·범위·비목표

비로그인 방문자가 서울에서 가까운 공동 주문 모집을 발견하고 신청 전에 공개 조건을 확인한다.

- 포함: 모집 중인 모집 표시, 마감 시 일반 마커 제거와 열린 모달의 마감 표시 예외, 공개 상세 확인, 수령·식사 방식과 계산 방식 확인, 공개용 대략 위치 표시.
- 비목표·경계: 모집 생성·참여 신청, 정확한 장소 공개, 채팅 참여는 다른 기능 명세에서 다룬다. 탐색 필터·목록·군집화와 SSE의 상세 설계는 아직 확정하지 않는다.

확정은 원본 PRD의 합의 내용이다. 제안·미정은 승인되지 않았다. 아래 시나리오와 SC는 확정 요구사항도 검증 가능한 문장으로 구체화한 검토용 제안이며, 실제 검증 통과를 의미하지 않는다.

### 후속 사용자 결정 — 2026-10-08

- 기본 탐색에는 모집 중인 모집만 표시한다. 모달을 열어 둔 모집이 마감된 경우 아래 예외를 적용한다.
- 일반 마커는 정상 연결에서 서버 마감 확정 후 2초 이내 새로고침 없이 제거한다.
- 모달이 열린 모집은 같은 2초 이내 마커를 회색 ‘마감’ 표시로 바꾼다.
  모달은 유지하고 마감 안내와 비활성화된 참여 버튼을 표시한다.
- 사용자가 모달을 닫으면 남겨 둔 해당 마감 마커도 제거한다.
  이 표시는 보고 있던 모집의 위치를 연결하는 예외이며 마감 모집의 일반 탐색을 허용하지 않는다.
- 위 항목은 이번 대화에서 확정했으며 노션 원본에는 아직 반영하지 않았다.
- 제거 애니메이션의 채택·세부 동작과 연결 끊김·복구 동작은 미정이다.
- 지도 상태 갱신에는 SSE를 사용한다. 그룹 채팅의 통신 방식은 별도 결정한다.

### 첫 구현 범위 — SDD 한 사이클 경험

2026-10-08 사용자는 모든 기능의 문서 작업을 먼저 끝내는 대신 지도 기능을
명세·설계·TDD 구현·검증까지 진행하여 SDD 한 사이클을 경험하기로 했다.

- **승인된 범위**: 실제 지도, 시험 모집 데이터, 비로그인 공개 상세 모달,
  실제 SSE 마감 알림, FR-006~009의 마커·모달 처리, 연결 끊김·복구 및
  빈 상태·조회 실패 처리, PC·모바일 화면 확인.
- **이번에 제외**: 회원가입·로그인, 모집 생성·참여 신청, 채팅, 결제,
  실제 운영 데이터 연동. 시험용 마감 조작으로 SSE 동작을 검증한다.
- **완료의 의미**: 시험 데이터 환경에서 지도 기능의 합의한 수용 조건을 검증한다.
  서비스 전체 또는 실제 운영 준비 완료를 의미하지 않는다.
- **진행 원칙**: 다른 기능의 명세 확정을 기다리지 않는다. 기존 001 문서를 사용하고,
  이번 구현에 필요한 결정만 마무리한다. 명세·설계·TDD 단계별 사용자 리뷰는 유지한다.
- **지도 공급자**: 네이버 지도 사용을 사용자가 선택했다(2026-10-08).
- **남은 결정**: 시험 공개 데이터·위치, 오류·복구의 구체적인 화면 동작,
  시험 환경. 실제 위치 생성 정책과 회원별 권한 검증은 후속 기능으로 남긴다.

### 기술 선택 기록 — 지도 공급자

- **결정**: 네이버 지도. 사용자 지정에 따른 선택이며 카카오맵 제안은 채택하지 않았다.
- **웹 연동**: NAVER Maps JavaScript API v3 / Web Dynamic Map을 사용한다.
- **설정 확인**: 사용자가 애플리케이션과 Client ID 준비 완료를 알렸다.
  실제 로컬 환경의 인증·지도 로딩 성공 여부는 구현 후 검증한다.
- **공식 문서**: https://navermaps.github.io/maps.js.ncp/docs/

### 기술 선택 기록 — 지도 상태 갱신

- **결정**: 2026-10-08 사용자가 SSE를 선택했다.
- **이유**: 지도는 서버의 모집 상태 변경을 브라우저로 전달받는 흐름이 중심이다.
  사용자 행동에 따른 상태 변경 요청과 서버의 변경 알림을 구분한다.
- **비교한 대안**: WebSocket의 양방향 메시지 통신을 검토했으며, 이번 지도 갱신에는 SSE를 선택했다.
- **후속 설계**: 상태 변경 API, SSE 이벤트 형식·구독 범위, 재연결·누락 복구,
  이벤트 수신 후 재조회 또는 캐시 직접 갱신 방식은 설계 단계에서 검토한다.
- **검증 경계**: SSE 선택만으로 반영 시간이나 장애 복구를 보장하지 않는다.
  마감 반영 목표는 2초 이내로 합의했으며 시험 환경·복구 후 기대 동작은 별도로 정한다.

기술 선택은 위 기록으로 관리하며 FR·SC는 사용자에게 보이는 지도 동작을 기준으로 검증한다.

### 첫 구현 명세 — 사용자 승인(2026-10-08)

사용자는 보완안을 검토한 뒤 “설계로 넘어가보자”라고 지시했다.
아래 M 요구사항은 이번 시험 데이터 구현에 한정하여 기존 FR-001,
FR-006~009와 함께 이번 설계·구현의 승인된 기준으로 사용한다. 아래에서 좁힌 범위 밖의
전체 제품 미정 사항은 후속 작업으로 남기며 이번 완료 조건으로 삼지 않는다.

- **M-01 · 시험 데이터와 탐색**: 서울 연남동 주변의 가상 모집을 사용하고 화면에
  ‘시험 데이터’를 표시한다. 공개 상세는 가상 가게명·음식·모임 예정 시각·수령/식사
  방식·계산 방식·모집 상태만 제공한다. 공개용 좌표는 시험용으로 별도 준비하고
  실제 개인 주소·정확한 만남 장소·채팅을 데이터와 공개 응답에 포함하지 않는다.
  현재 위치 권한·지역 검색 없이 지도 이동과 확대/축소로 탐색한다.
  서울 밖으로 지도 이동은 가능하지만 시험 모집 외 데이터는 제공하지 않는다.
- **M-02 · 참여 경계**: 모집 중에도 참여 버튼은 ‘참여 기능 준비 중’으로 비활성화한다.
  마감 시 ‘모집 마감’으로 바꾸고 비활성 상태를 유지한다. 로그인 화면으로 이동하거나
  실제 참여 요청을 보내지 않는다. 마커 제거 애니메이션은 이번에 추가하지 않는다.
- **M-03 · 연결 복구**: 연결 실패 감지 시 기존 지도·모달을 유지하고
  ‘실시간 연결이 끊겼어요. 다시 연결하고 있어요.’를 표시한다.
  재연결 시 최신 상태를 조회하여 연결 중 누락된 마감을 반영한다.
  열린 모달의 모집도 확인하며 FR-008~009 예외를 적용한다.
  최신 상태 확인이 성공한 뒤에만 연결 안내를 숨긴다.
- **M-04 · 빈 상태와 오류**: 현재 화면 영역에 모집 중인 항목이 없으면
  ‘이 지역에는 모집 중인 모임이 없어요’를 표시하고 지도 이동을 계속 허용한다.
  지도 로딩 실패와 모집 조회 실패는 각각 오류·재시도 수단을 표시한다.
  조회 실패를 모집 0건으로 표현하지 않고, 기존 데이터가 있다면 갱신 실패 안내와
  함께 유지한다. 최초 조회 중에는 로딩 상태를 표시한다.
- **M-05 · 검증 범위**: 로컬 실행 환경, 네트워크 제한 없는 전경 브라우저에서
  1440×900 및 390×844 화면으로 검증한다. 자동화 브라우저 이름·버전은 결과에 기록하고,
  모바일 크기 검증과 실제 휴대폰 검증을 구분한다. 네이버 지도 실제 로딩은 별도 확인한다.
  서로 다른 두 세션 중 하나에서 시험 모집을 마감하고 다른 세션의 화면 변화를 관찰한다.
  일반 마커 제거 및 열린 모달 마감 전환을 각각 5회 측정하여 매회 2초 이내인지 확인한다.
  실제 측정 방법은 설계에 기록한다. 이 결과를 운영 환경 성능 보장으로 확대하지 않는다.

**이번 인수 조건**:

- **MC-01**: 로그인 없이 시험 모집 마커와 M-01 공개 상세를 확인하고,
  공개 응답·페이지 데이터에 실제 개인 위치나 채팅이 없는지 검사한다. [M-01, FR-001]
- **MC-02**: 모집 중·마감이 섞인 데이터에서 초기에는 모집 중만 표시한다.
  일반 마감, 열린 모달 마감, 모달 닫기, 두 모집의 동시 마감을 검증한다.
  M-05의 모든 시간 측정이 2초 이내다. [FR-006~009, SC-004~007]
- **MC-03**: 연결이 끊긴 동안 마감한 모집도 재연결·최신 상태 조회 후 올바르게 반영하며,
  동기화 실패 시 정상 연결 안내로 돌아가지 않는다. [M-03]
- **MC-04**: 최초 로딩·영역 내 모집 없음·지도 실패·조회 실패와 재시도를 각각 확인한다.
  두 화면 크기에서 마커 선택·상세 읽기·모달 닫기가 가능하다. [M-04~05]
- **MC-05**: 모집 중·마감 모두 실제 참여 요청이 발생하지 않고,
  시험용 마감 조작은 로컬 검증용으로만 제공한다. [M-02]

전체 SC-002의 승인자 정보 비교는 인증 기능 이후 검증한다. 이번에는 MC-01의 공개
데이터 제한만 검증하며 회원별 권한 검증 완료로 보고하지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 근처 모집 찾기 (P1)

방문자가 로그인 없이 지도에서 모집을 찾는다.

**우선순위 이유**: 핵심 진입 경로이며 로그인 이전에 서비스 가치를 확인할 수 있다.
**개별 검증**: 공개 가능한 시험 모집을 준비하고 비로그인 계정으로 지도에서 선택한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 비로그인 방문자와 공개 가능한 시험 모집이 있을 때 **행동**: 지도에서 해당 모집을 선택하면 **기대 결과**: 로그인을 요구하지 않고 공개 상세를 확인할 수 있다. [AC-01]
2. **주어진 조건**: 공개 상세를 확인 중일 때 **행동**: 수령·식사 방식과 계산 방식을 확인하면 **기대 결과**: 각자 가져가기/함께 먹기와 개별 메뉴값/균등 분할 중 등록된 선택을 확인할 수 있다. [REQ-04, AC-03 연결]

### 사용자 이야기 2 — 공개 위치 확인 (P1)

방문자가 음식 수령·식사 장소의 대략적인 위치만 확인한다.

**우선순위 이유**: 참여 전 탐색과 정확한 장소 공개를 구분한다.
**개별 검증**: 정확한 장소가 다른 두 시험 모집의 공개 정보와 승인자 정보를 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 아직 승인되지 않은 방문자일 때 **행동**: 공개 지도와 상세를 열면 **기대 결과**: 대략적인 모임 위치는 확인하지만 정확한 장소와 채팅 내용은 볼 수 없다. [AC-01]

### 사용자 이야기 3 — 마감된 모집의 실시간 제외 (P1)

방문자는 모집 중인 모집을 탐색한다. 마감된 일반 마커는 제거하고 모달이 열린 모집은 마감 표시로 유지한다.

**우선순위 이유**: 이미 마감된 모집을 참여 가능한 모집으로 오인하지 않도록 한다.
**개별 검증**: 모집 중·마감 상태의 시험 모집으로 처음 지도를 조회하고,
다른 세션에서 모집 중인 항목을 마감하여 현재 화면의 변화를 관찰한다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 모집 중과 마감 상태의 모집이 있을 때 **행동**: 지도를 조회하면 **기대 결과**: 모집 중인 모집만 지도에 표시된다. [FR-006]
2. **주어진 조건**: 정상 연결에서 모달을 열지 않은 모집이 지도에 보일 때 **행동**: 해당 모집이 마감되면 **기대 결과**: 서버의 마감 확정 후 2초 이내 새로고침 없이 지도에서 제거된다. [FR-007]

3. **주어진 조건**: 정상 연결에서 모집 상세 모달을 보고 있을 때 **행동**: 해당 모집이 마감되면 **기대 결과**: 서버 마감 확정 후 2초 이내 마커는 회색 ‘마감’ 표시로 바뀌고 모달은 마감 안내·비활성 참여 버튼과 함께 유지된다. [FR-008]
4. **주어진 조건**: 마감 표시와 모달이 유지된 상태일 때 **행동**: 사용자가 모달을 닫으면 **기대 결과**: 해당 마감 마커도 제거된다. [FR-009]
5. **주어진 조건**: 두 모집 중 하나의 모달만 열려 있을 때 **행동**: 두 모집이 모두 마감되면 **기대 결과**: 모달이 열린 모집만 마감 표시로 유지하고 다른 마커는 제거한다. [FR-006~009]

### 경계 사례

- 해당 지도 영역에 모집이 없음: 빈 상태 안내와 다른 지역 탐색 수단을 제안한다. 사용자 검토 전이다.
- 지도·모집 조회 실패: 성공하거나 모집이 없는 것처럼 표시하지 않고 실패와 재시도 수단을 안내하는 안을 제안한다.
- 지도에 표시된 모집이 마감됨: 일반 마커는 제거한다. 모달이 열린 모집은 마감 표시와 안내로 전환하고 모달을 닫으면 마커도 제거한다.
- 실시간 연결이 끊기거나 복구됨: 상태 안내·재조회·복구 시 화면 정합성 규칙은 미정이다.
- 모집이 취소 상태가 됨: 모집 중이 아닌 항목은 지도 표시 대상에서 제외한다. 취소 상태의 정의와 전환 규칙은 005 및 OPEN-10에서 정한다.
- 서울 외 지역으로 이동: 탐색 허용·안내·등록 제한의 경계는 미정이다.

## 요구사항

### 기능 요구사항

- **FR-001 · 확정**: 비로그인 방문자에게 지도 탐색과 공개 상세 열람을 제공한다. 출처: REQ-01.
- **FR-002 · 확정**: 공개 위치는 수령·식사 장소의 대략적인 위치이며 음식점 위치나 사용자 집 주소를 기본 공개 위치로 취급하지 않는다. 출처: REQ-06, PRD 6장.
- **FR-003 · 확정**: 승인 전에는 정확한 장소와 그룹 채팅을 공개하지 않는다. 출처: REQ-06, REQ-07.
- **FR-004 · 제안**: 정확한 좌표·주소는 공개 조회 응답과 공개 페이지 데이터에도 포함하지 않는다. 출처: PRD 11장, AC-05.
- **FR-005 · 제안**: 기기 위치 권한을 거절한 방문자는 지역 검색 또는 지도 이동으로 탐색할 수 있다. 출처: PRD 11장.
- **FR-006 · 확정(후속 사용자 결정)**: 기본 탐색에는 모집 중인 모집만 표시한다. 모달이 열린 모집의 마감은 FR-008~009의 임시 표시 예외를 적용한다. 출처: 2026-10-08 대화, REQ-01 구체화.
- **FR-007 · 확정(후속 사용자 결정)**: 모달을 열지 않은 모집이 마감되면 정상 연결에서 서버 마감 확정 후 2초 이내 새로고침 없이 지도에서 제거한다. 연결 실패·복구 규칙은 미정이다. 출처: 2026-10-08 대화, REQ-01·REQ-09 연결.

- **FR-008 · 확정(후속 사용자 결정)**: 모달이 열린 모집이 마감되면 정상 연결에서 서버 마감 확정 후 2초 이내 마커를 회색 ‘마감’ 표시로 전환한다. 모달을 강제로 닫지 않고 마감 안내와 비활성화된 참여 버튼을 표시한다. 출처: 2026-10-08 대화.
- **FR-009 · 확정(후속 사용자 결정)**: 사용자가 마감된 모집의 모달을 닫으면 임시로 남긴 마감 마커도 제거한다. 출처: 2026-10-08 대화.

### 주요 데이터 개념

- 공개 모집: 공개가 허용된 가게·음식·시간·방식·상태 정보. 필드 확정은 003에 의존한다.
- 공개 위치: 정확한 장소로부터 구분되는 대략적인 모임 위치. 정밀도와 생성 규칙은 미정이다.

## 완료 조건

### 측정 가능한 검증 결과 — 검토용 제안

- **SC-001**: 시험 모집을 비로그인으로 선택하여 공개 상세 확인 시나리오를 모두 통과한다. [AC-01]
- **SC-002**: 공개/승인자 정보 비교에서 승인 전 정확한 장소와 채팅 내용의 노출이 0건이다. 공개 응답 검사는 제안 채택 후 수행한다. [AC-01, AC-05]
- **SC-003**: 합의한 PC·모바일 환경 모두에서 탐색과 상세 확인을 수행한다. 환경 확정 전에는 검증 대기다. [AC-17, OPEN-11]
- **SC-004**: 초기 지도 조회에서 모집 중이 아닌 모집의 표시가 0건이다. [FR-006]
- **SC-005**: 정상 연결에서 모달을 열지 않은 모집은 서버 마감 확정부터 지도 제거 완료까지 2초 이내이며 새로고침이 필요하지 않다. 시각적 전환 채택 시 그 완료까지 측정한다. 시험 환경·측정 방법은 미정이며 검증은 미실행이다. [FR-007, OPEN-11]

- **SC-006**: 정상 연결에서 모달이 열린 모집의 마감 확정 후 2초 이내 마커·모달·참여 버튼이 모두 마감 상태를 표시하며 모달은 유지된다. [FR-008]
- **SC-007**: 마감된 모집의 모달을 닫은 후 해당 마감 마커가 남는 사례가 0건이다. 다른 모집의 마감에는 이 예외를 적용하지 않는다. [FR-006, FR-009]

이 기능의 검증 결과는 관련 PRD AC로 추적한다. 제품 성과 지표의 목표값·관찰 기간은 OPEN-07에서 별도로 결정한다.

- **Q-03 · 시험 환경** (OPEN-11): [NEEDS CLARIFICATION: 지원 브라우저·화면 크기·지도 탐색 성능 목표와 마감 반영 2초 기준의 시험 조건·측정 방법을 정한다.]

## 가정·의존성·호환성

- 003이 제공할 공개 모집 데이터와 002/007의 위치 공개 정책에 의존한다. 공급자 결정은 설계 단계의 입력이다.
- 이 명세는 새 프로젝트에 적용한다. 기존 비공개 프로젝트의 코드·데이터를 가져오거나 기존 사용자 데이터를 이전하는 요구는 포함하지 않는다.
- 한국어 PC·모바일 웹 지원은 전체 제약이다. 기술 선택은 승인된 명세의 후속 설계에서 다룬다.
- 각 단계에 사용자 리뷰·검증을 포함한다. 구현 계획·작업 목록을 작성했고 지도 표시 코드를 구현했다. 화면 Green 사용자 리뷰와 후속 기능 구현은 남아 있다.
