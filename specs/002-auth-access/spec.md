## 목적·범위·비목표

공개 탐색은 허용하면서 모집 생성·신청·채팅과 정확한 장소 조회를 사용자 상태에 맞게 제한한다.

- 포함: 로그인 필요 행동의 진입, 모집자·승인 참가자의 접근, 비인가 요청 제한.
- 비목표·경계: 지도·채팅·참여 관리의 본문 동작은 해당 명세에서 다룬다. 로그인 공급자·수집 정보·계정 삭제 방식은 결정 전이다.

확정은 원본 PRD의 합의 내용이다. 제안·미정은 승인되지 않았다. 아래 시나리오와 SC는 확정 요구사항도 검증 가능한 문장으로 구체화한 검토용 제안이며, 실제 검증 통과를 의미하지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 로그인 후 행동 수행 (P1)

비로그인 사용자가 등록·참여·채팅을 시도하면 로그인이 필요함을 확인한다.

**우선순위 이유**: 사용자 식별이 필요한 행동의 진입 조건을 통일한다.
**개별 검증**: 비로그인 상태에서 세 행동을 각각 시도한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 비로그인 상태일 때 **행동**: 모집 등록·참여 신청·채팅을 시도하면 **기대 결과**: 로그인 화면을 표시한다. [AC-02]
2. **주어진 조건**: 인증되지 않은 상태일 때 **행동**: 제한된 행동을 직접 요청하면 **기대 결과**: 요청이 실행되지 않는다. [AC-02, 검증 조건 제안]

### 사용자 이야기 2 — 참여 상태별 정보 접근 (P1)

모집자와 승인 참가자만 정확한 장소와 해당 그룹 채팅에 접근한다.

**우선순위 이유**: 모집별 정보 접근 경계를 확인한다.
**개별 검증**: 모집자·승인자·대기자·거절자·무관한 계정을 준비하여 접근을 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 모집자 또는 해당 모집의 승인 참가자일 때 **행동**: 정확한 장소와 채팅을 요청하면 **기대 결과**: 해당 모집의 장소·채팅에 접근할 수 있다. [AC-05]
2. **주어진 조건**: 비로그인·대기·거절·무관한 계정일 때 **행동**: 정확한 장소 또는 채팅을 직접 요청하면 **기대 결과**: 접근이 거절된다. [AC-05, 대기·거절 세부 규칙 제안]

### 경계 사례

- 로그인 실패·취소: 제한된 행동이 실행되지 않아야 한다. 오류 안내·복귀 방식은 미정이다.
- 세션 만료 중 작성·전송: 입력 보존·재로그인 동작은 미정이다.
- 같은 사용자의 다른 모집 접근: 승인은 모집 단위이며 다른 모집의 권한을 부여하지 않는다.
- 재승인 대기·참여 취소와 조회가 동시에 발생: 권한 적용 시점과 검증 조건은 결정 전이다.

## 요구사항

### 기능 요구사항

- **FR-001 · 확정**: 등록·참여 신청·채팅 시 로그인 여부를 확인하고 필요하면 로그인 화면을 제공한다. 출처: REQ-02.
- **FR-002 · 확정**: 모집자와 해당 모집의 승인 참가자에게만 정확한 장소와 그룹 채팅을 제공한다. 출처: REQ-06, REQ-07.
- **FR-003 · 제안**: 로그인 후 시도하던 행동으로 복귀한다. 출처: PRD 5장.
- **FR-004 · 제안**: 장소·채팅·신청·모집 변경마다 사용자와 해당 모집의 참여 상태를 검증한다. 출처: PRD 11장, AC-02, AC-05.
- **FR-005 · 제안**: 대기·거절자는 공개 정보와 본인 신청만 열람하며 정확한 장소·채팅은 열람하지 못한다. 출처: PRD 5장.
- **FR-006 · 제안**: 참여 취소·탈퇴 후 이후 장소 조회·채팅 접근을 차단한다. 적용 시점과 남은 기록의 접근은 별도 결정한다. 출처: PRD 5장, OPEN-05, OPEN-08.

### 주요 데이터 개념

- 계정: 사용자 식별과 표시 이름. 공급자와 수집 필드는 미정이다.
- 모집별 역할: 모집자, 승인 참가자, 대기·거절·취소 사용자. 다른 모집으로 권한을 확장하지 않는다.
- 인증 상태: 로그인 여부와 제한된 행동 수행 자격. 세션 정책은 설계 전 결정한다.

## 완료 조건

### 측정 가능한 검증 결과 — 검토용 제안

- **SC-001**: 비로그인 등록·신청·채팅 시도 각각에서 로그인 안내가 제공된다. [AC-02]
- **SC-002**: 채택된 직접 요청 검증에서 비인가 행동 실행과 장소·채팅 접근 성공이 0건이다. [AC-02, AC-05]
- **SC-003**: 승인 참가자가 본인 모집에 접근하고 무관한 모집에는 접근하지 못하는 역할별 검증을 통과한다. [AC-05]

이 기능의 검증 결과는 관련 PRD AC로 추적한다. 제품 성과 지표의 목표값·관찰 기간은 OPEN-07에서 별도로 결정한다.

## 가정·의존성·호환성

- 004의 참여 상태와 005의 모집 상태를 사용하며, 007과 동일한 접근 규칙을 공유한다.
- 이 명세는 새 프로젝트에 적용한다. 기존 비공개 프로젝트의 코드·데이터를 가져오거나 기존 사용자 데이터를 이전하는 요구는 포함하지 않는다.
- 한국어 PC·모바일 웹 지원은 전체 제약이다. 기술 선택은 승인된 명세의 후속 설계에서 다룬다.
- 각 단계에 사용자 리뷰·검증을 포함한다. 현재 구현 계획·작업 목록·제품 코드는 작성하지 않았다.
