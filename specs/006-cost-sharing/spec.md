# 기능 명세: 참가자별 부담 금액 계산

**작성일**: 2026-10-06
**상태**: 초안 — 사용자 검토·승인 전
**브랜치**: 별도 기능 브랜치 미생성
**입력**: 노션 PRD v0.1을 기준으로 전체 범위를 기능별로 분해하라는 사용자 요청
**PRD 연결**: REQ-08 · AC-07~08

[전체 범위·원본·협업 원칙](../README.md)

## 목적·범위·비목표

개별 메뉴값 또는 균등 분할 방식으로 참가자가 부담할 금액을 확인하고 외부에서 직접 정산한다.

- 포함: 계산 방식별 부담 금액 표시, 모집자 포함, 음식값·배달비 구분, 승인 변경의 계산 영향.
- 비목표·경계: 송금·입금 확인·내부 결제·환불은 제공하지 않는다. 할인·추가 비용·나머지·예상/최종 가격 규칙은 확정 전이다.

확정은 원본 PRD의 합의 내용이다. 제안·미정은 승인되지 않았다. 아래 시나리오와 SC는 확정 요구사항도 검증 가능한 문장으로 구체화한 검토용 제안이며, 실제 검증 통과를 의미하지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 개별 메뉴 부담액 확인 (P1)

참가자가 자기 음식값을 기준으로 분담액을 확인한다.

**우선순위 이유**: 필요한 음식과 비용을 부담하는 핵심 가치다.
**개별 검증**: 확정될 배달비 정책을 적용한 시험 주문의 금액을 손계산과 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 배달비 균등 분담 제안을 채택하고 음식값 9,000원·11,000원, 배달비 2,000원일 때 **행동**: 두 참가자의 부담액을 계산하면 **기대 결과**: 각각 10,000원·12,000원이다. [AC-07, 조건부 제안]

### 사용자 이야기 2 — 균등 분할 부담액 확인 (P1)

참가자가 전체 음식값과 배달비를 인원수로 나눈 금액을 확인한다.

**우선순위 이유**: 선택한 계산 방식의 결과를 제공한다.
**개별 검증**: 모집자 포함 3명의 시험 주문을 손계산과 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 균등 분할, 음식값 24,000원·배달비 3,000원·모집자 포함 3명일 때 **행동**: 부담액을 계산하면 **기대 결과**: 각각 9,000원으로 표시한다. [AC-08]

### 경계 사례

- 나누어떨어지지 않는 금액: 원 단위 나머지 배분은 미정이다.
- 할인·쿠폰·추가 비용: 수혜자와 적용 순서·분배 방식은 미정이다.
- 승인 취소·재승인 대기·최종 금액 변경: 계산 대상과 예상/최종 구분, 참가자 확인 규칙은 미정이다.
- 0명·음수·과도한 입력: 유효성 범위와 계산 불가 안내는 입력 정책에서 확정한다.

## 요구사항

### 기능 요구사항

- **FR-001 · 확정**: 개별 메뉴에서는 각자의 음식값을 기준으로 부담액을 계산한다. 배달비의 구체적인 배분 규칙은 미정이다. 출처: REQ-08, PRD 9장.
- **FR-002 · 확정**: 균등 분할에서는 전체 음식값과 배달비를 인원수로 나누는 형태를 지원한다. 할인·나머지 처리 규칙은 미정이다. 출처: REQ-08.
- **FR-003 · 확정**: 모집자를 계산 인원과 음식값에 포함한다. 출처: PRD 9장.
- **FR-004 · 확정**: 배달비를 자동 마감용 목표 음식값 합계에 넣지 않는다. 출처: REQ-10 연결.
- **FR-005 · 제안**: 개별 메뉴 부담액은 본인 음식값과 배달비 균등 분담액의 합으로 계산한다. 출처: PRD 9장, AC-07.
- **FR-006 · 제안**: 최종 부담액의 합은 입력된 최종 결제액과 일치해야 한다. 출처: PRD 9장.
- **FR-007 · 제안**: 표시된 계산 금액을 송금 완료나 실제 입금으로 표현하지 않는다. 출처: PRD 9장.

### 주요 데이터 개념

- 음식값: 참가자별 메뉴 금액 또는 전체 음식 금액.
- 배달비·할인·추가 비용: 음식값과 구분되는 계산 입력. 분담 정책은 미정이다.
- 부담액: 모집자와 계산 대상 참가자별 금액. 예상/최종 구분 정책은 미정이다.

## 완료 조건

### 측정 가능한 검증 결과 — 검토용 제안

- **SC-001**: 배달비 균등 분담 채택 후 개별 메뉴 예시를 손계산과 일치시킨다. [AC-07]
- **SC-002**: 균등 분할 예시에서 3명 모두 9,000원이다. [AC-08]
- **SC-003**: 나머지·할인·최종 가격 정책 확정 후 각 경계 사례에서 계산 결과와 총합이 합의한 규칙에 일치한다. 현재는 검증 대기다. [OPEN-01, OPEN-02]

이 기능의 검증 결과는 관련 PRD AC로 추적한다. 제품 성과 지표의 목표값·관찰 기간은 OPEN-07에서 별도로 결정한다.

질문은 관련 결정을 묶은 검토 항목이다. 결정되지 않은 동작을 구현자가 임의로 확정하지 않는다. 원본 OPEN 목록의 승인·변경도 사용자 검토 후 반영한다.

## 가정·의존성·호환성

- 003의 계산 방식·음식값·배달비와 004의 승인/취소 상태에 의존한다. 005가 사용하는 마감용 합계와 사용자 부담액은 구별한다.
- 이 명세는 새 프로젝트에 적용한다. 기존 비공개 프로젝트의 코드·데이터를 가져오거나 기존 사용자 데이터를 이전하는 요구는 포함하지 않는다.
- 한국어 PC·모바일 웹 지원은 전체 제약이다. 기술 선택은 승인된 명세의 후속 설계에서 다룬다.
- 각 단계에 사용자 리뷰·검증을 포함한다. 현재 구현 계획·작업 목록·제품 코드는 작성하지 않았다.
