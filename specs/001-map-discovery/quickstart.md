# 지도 검증 가이드

상태: 구현 전 실행 예정 안내. 아래 명령의 스크립트도 구현 단계에서 생성한다.

## 실행 준비

1. 설계 승인 후 앱·테스트 설정을 생성하고 npm 의존성 버전을 lockfile에 고정한다.
2. .env.local에 NEXT_PUBLIC_NAVER_MAP_CLIENT_ID=<발급받은 Client ID> 설정.
   .env.local은 Git 제외하며 .env.example에는 값 없이 이름만 기록한다. Client Secret은 필요 없다.
3. 네이버 Maps 웹 서비스 URL이 로컬 접속 주소를 허용하는지 확인한다.
4. npm run dev (루프백 바인딩). 시험 조작은 MAP_DEMO_CONTROLS=1인 별도 로컬 실행에서 활성화한다.

## 검증

- npm test: 표시 규칙·동기화·API 테스트. 각 TDD 단위의 최초 의도한 실패와 통과를 기록.
- npm run test:e2e: 실제 서버·HTTP·SSE를 사용하는 두 세션 시험. 1440×900, 390×844.
- npm run lint, npm run typecheck, npm run build: 구현 후 실행 결과 기록.
- 공개 응답 허용 필드 검사, 초기 open만 표시, 열린 상세와 일반 마커 동시 마감,
  닫기·초기 로딩·빈 영역·지도 오류·조회 오류·재시도 확인.
- 선택한 모집을 연결 단절 중 마감 후 재연결. 최신 조회가 완료되기 전 정상 표시 금지 확인.
  느린 조회와 추가 마감 알림을 겹쳐 오래된 상태가 되살아나지 않는지 확인.
- 네이버 SDK 대역을 쓰는 자동화는 앱 규칙 검증이다. 실제 SDK/지도/키는 별도 브라우저에서
  지도 로드·이동·마커·모달을 직접 확인한다. 실제 지도로 두 세션 마감도 확인한다.

## 2초 측정

일반 마커와 열린 모달 사례 각각 5회. Next 개발 컴파일 영향을 피하려고 빌드 후 로컬 실행한다.
시험 실행기가 POST 전후 서버 시각과 브라우저 시각 차이를 추정하여 오차 구간을 기록한다.
서버 closedAt부터 실제 DOM/마커의 기대 상태가 그려진 프레임까지 측정한다.
오차를 더한 상한도 2000ms 이하여야 통과. 이벤트 도착 시간만으로 통과시키지 않는다.
브라우저 전경·네트워크 제한 없음·버전·각 회차 결과를 남긴다. 가짜 타이머로 성능을 측정하지 않는다.
SDK 대역 시간과 실제 네이버 지도 시간을 구분하고 실지도 미측정이면 해당 조건은 미검증으로 남긴다.

## 사용자 확인

두 창에서 마감 조작과 화면 반영, 모바일 크기에서 상세 읽기·닫기를 직접 확인한다.
화면 크기 시험은 실제 휴대폰 검증을 대체했다고 표현하지 않는다.
결과를 MC-01~05별 통과/실패/미검증으로 보고한다. 커밋은 코드 설명·별도 지시 이후다.


## 지도 표시 Green 검증 — 2026-10-08

- 실제 접속 주소: http://localhost:3000 (npm run dev).
- 127.0.0.1에서는 네이버 인증 실패 화면, localhost에서는 실제 지도 표시 성공.
  개발 서버는 루프백에 바인딩하지만 브라우저에서는 등록된 localhost 주소로 접속한다.
- 인앱 브라우저 1440×900에서 헤더·검색·목록/지도 배치와 실제 지도 확인.
- 지도 확대 후 축척 100m→50m, 드래그 이동 및 축소 조작 확인.
- 390×844에서 지도 표시·가로 넘침 없음 확인(문서 폭=뷰포트 폭=390).
  실제 휴대폰 터치 검증은 아직 하지 않았다.
- 공개 키 값은 문서·로그에 기록하지 않는다. 네이버 인증 실패를 별도 앱 안내로
  처리하는 경로는 현재 미검증이며 SDK 파일 로딩 실패와 구분한다.
- 모집·SSE·모달 및 MC 전체 검증은 후속 작업이다. 첫 화면 Green 사용자 리뷰 대기.
