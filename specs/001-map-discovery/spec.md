## 목적·범위·비목표

비로그인 방문자가 서울에서 가까운 공동 주문 모집을 발견하고 신청 전에 공개 조건을 확인한다.

- 포함: 지도에서 모집 선택, 공개 상세 확인, 수령·식사 방식과 계산 방식 확인, 공개용 대략 위치 표시.
- 비목표·경계: 모집 생성·참여 신청, 정확한 장소 공개, 채팅 참여는 다른 기능 명세에서 다룬다. 탐색 필터·목록·군집화·자동 갱신 방식은 아직 확정하지 않는다.

확정은 원본 PRD의 합의 내용이다. 제안·미정은 승인되지 않았다. 아래 시나리오와 SC는 확정 요구사항도 검증 가능한 문장으로 구체화한 검토용 제안이며, 실제 검증 통과를 의미하지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 근처 모집 찾기 (P1)

방문자가 로그인 없이 지도에서 모집을 찾는다.

**우선순위 이유**: 핵심 진입 경로이며 로그인 이전에 서비스 가치를 확인할 수 있다.
**개별 검증**: 공개 가능한 시험 모집을 준비하고 비로그인 계정으로 지도에서 선택한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 비로그인 방문자와 공개 가능한 시험 모집이 있을 때 **행동**: 지도에서 해당 모집을 선택하면 **기대 결과**: 로그인을 요구하지 않고 공개 상세를 확인할 수 있다. [AC-01]
2. **주어진 조건**: 공개 상세를 확인 중일 때 **행동**: 수령·식사 방식과 계산 방식을 확인하면 **기대 결과**: 각자 가져가기/함께 먹기와 개별 메뉴값/균등 분할 중 등록된 선택을 확인할 수 있다. [REQ-04, AC-03 연결]

### 사용자 이야기 2 — 공개 위치 확인 (P1)

방문자가 음식 수령·식사 장소의 대략적인 위치만 확인한다.

**우선순위 이유**: 참여 전 탐색과 정확한 장소 공개를 구분한다.
**개별 검증**: 정확한 장소가 다른 두 시험 모집의 공개 정보와 승인자 정보를 비교한다. 공통 의존 기능 또는 합의한 시험 데이터를 준비한다. 이 시험만으로 서비스 전체 완료를 선언하지 않는다.

**수용 시나리오 — 검토용 제안**:

1. **주어진 조건**: 아직 승인되지 않은 방문자일 때 **행동**: 공개 지도와 상세를 열면 **기대 결과**: 대략적인 모임 위치는 확인하지만 정확한 장소와 채팅 내용은 볼 수 없다. [AC-01]

### 경계 사례

- 해당 지도 영역에 모집이 없음: 빈 상태 안내와 다른 지역 탐색 수단을 제안한다. 사용자 검토 전이다.
- 지도·모집 조회 실패: 성공하거나 모집이 없는 것처럼 표시하지 않고 실패와 재시도 수단을 안내하는 안을 제안한다.
- 열어 둔 모집이 마감·취소됨: 상태별 공개 유지·지도 제외·갱신 시점은 미정이다.
- 서울 외 지역으로 이동: 탐색 허용·안내·등록 제한의 경계는 미정이다.

## 요구사항

### 기능 요구사항

- **FR-001 · 확정**: 비로그인 방문자에게 지도 탐색과 공개 상세 열람을 제공한다. 출처: REQ-01.
- **FR-002 · 확정**: 공개 위치는 수령·식사 장소의 대략적인 위치이며 음식점 위치나 사용자 집 주소를 기본 공개 위치로 취급하지 않는다. 출처: REQ-06, PRD 6장.
- **FR-003 · 확정**: 승인 전에는 정확한 장소와 그룹 채팅을 공개하지 않는다. 출처: REQ-06, REQ-07.
- **FR-004 · 제안**: 정확한 좌표·주소는 공개 조회 응답과 공개 페이지 데이터에도 포함하지 않는다. 출처: PRD 11장, AC-05.
- **FR-005 · 제안**: 기기 위치 권한을 거절한 방문자는 지역 검색 또는 지도 이동으로 탐색할 수 있다. 출처: PRD 11장.

### 주요 데이터 개념

- 공개 모집: 공개가 허용된 가게·음식·시간·방식·상태 정보. 필드 확정은 003에 의존한다.
- 공개 위치: 정확한 장소로부터 구분되는 대략적인 모임 위치. 정밀도와 생성 규칙은 미정이다.

## 완료 조건

### 측정 가능한 검증 결과 — 검토용 제안

- **SC-001**: 시험 모집을 비로그인으로 선택하여 공개 상세 확인 시나리오를 모두 통과한다. [AC-01]
- **SC-002**: 공개/승인자 정보 비교에서 승인 전 정확한 장소와 채팅 내용의 노출이 0건이다. 공개 응답 검사는 제안 채택 후 수행한다. [AC-01, AC-05]
- **SC-003**: 합의한 PC·모바일 환경 모두에서 탐색과 상세 확인을 수행한다. 환경 확정 전에는 검증 대기다. [AC-17, OPEN-11]

이 기능의 검증 결과는 관련 PRD AC로 추적한다. 제품 성과 지표의 목표값·관찰 기간은 OPEN-07에서 별도로 결정한다.

## 미정 사항과 승인 전 결정

- **Q-02 · 탐색 실패와 권한 거절** (OPEN-06, PRD 11장): [NEEDS CLARIFICATION: 지도 공급자와 위치 거절 시 대안, 빈 상태·실패 동작을 결정한다.]
- **Q-03 · 시험 환경** (OPEN-11): [NEEDS CLARIFICATION: 지원 브라우저·화면 크기·지도 탐색 성능의 시험 조건과 목표를 정한다.]

질문은 관련 결정을 묶은 검토 항목이다. 결정되지 않은 동작을 구현자가 임의로 확정하지 않는다. 원본 OPEN 목록의 승인·변경도 사용자 검토 후 반영한다.

## 가정·의존성·호환성

- 003이 제공할 공개 모집 데이터와 002/007의 위치 공개 정책에 의존한다. 공급자 결정은 설계 단계의 입력이다.
- 이 명세는 새 프로젝트에 적용한다. 기존 비공개 프로젝트의 코드·데이터를 가져오거나 기존 사용자 데이터를 이전하는 요구는 포함하지 않는다.
- 한국어 PC·모바일 웹 지원은 전체 제약이다. 기술 선택은 승인된 명세의 후속 설계에서 다룬다.
- 각 단계에 사용자 리뷰·검증을 포함한다. 현재 구현 계획·작업 목록·제품 코드는 작성하지 않았다.
